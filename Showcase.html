Portal · Reservas

Agendamiento en 4 pasos

El flujo de reserva guía al cliente paso a paso. Cada paso valida la selección antes de avanzar. Al completarlo genera un ticket único con código QR.

Paso 01
Servicio
Elige entre el catálogo completo: corte, balayage, color, keratina, asesoría de imagen y más.
Paso 02
Estilista
Selecciona a un profesional específico o elige "Sin preferencia" para asignación automática por disponibilidad.
Paso 03
Fecha y hora
Calendario de hasta 3 días. Los horarios ocupados o bloqueados por admin aparecen deshabilitados automáticamente.
Paso 04
Datos personales
Nombre, teléfono y cédula. La cédula permite identificar al cliente en check-in y en el CRM.
  • Al confirmar se genera un ticket tipo JX-XXXX con código QR visual imprimible.
  • Si se elige "Sin preferencia", el sistema asigna automáticamente al estilista con menor carga ese día.
  • Los horarios bloqueados por el administrador no aparecen como disponibles.
  • La reserva queda sincronizada al instante en el panel admin sin intervención humana.
  • El catálogo de servicios y estilistas se carga dinámicamente desde la configuración del admin.

Portal · Operación

Escáner QR para el barbero

Herramienta para el personal del salón. Permite escanear el QR del cliente para ver su cita, confirmar check-in o moverla al siguiente estado desde el teléfono.

  • Accede a la cámara del dispositivo para leer códigos QR directamente desde el móvil o tablet del estilista.
  • Al detectar un código válido muestra los datos completos de la cita: cliente, servicio, hora y estado actual.
  • Permite mover la cita a "En silla" o marcarla como completada con un toque, sin ir al panel admin.
  • También acepta ingreso manual del código JX-XXXX si la cámara no está disponible.

Admin · Módulo

Agenda semanal

Vista de calendario semanal organizada por estilista. El administrador puede navegar entre semanas y ver de un vistazo quién tiene qué cita y cuándo.

  • Grilla semanal (lunes a sábado) con columnas por día y filas por estilista.
  • Cada cita aparece como un bloque con nombre del cliente, servicio y hora.
  • Navegación entre semanas con flechas. La semana actual resaltada por defecto.
  • Los horarios bloqueados se muestran con un marcador visual diferenciado.
  • Un clic sobre una cita abre el detalle completo con acciones: mover de estado, cancelar, ver cliente.

Admin · Módulo

Caja e ingresos

Registro de todos los cobros del salón. El administrador cierra cada cita con el método de pago utilizado. El sistema calcula los totales automáticamente.

◎

Métodos de pago

Soporta Efectivo, Transferencia, Datáfono y Nequi. Cada método tiene un color identificador en el registro.

Multi-método
◈

Resumen diario

Total del día desglosado por método de pago. Permite ver de un vistazo cuánto entró en efectivo vs transferencia.

Cierre de caja
≡

Historial de cobros

Todos los pagos registrados con fecha, cliente, servicio, estilista y monto. Filtrable por período.

✦

Notas por cobro

Campo de notas libre por cada registro de pago. Útil para descuentos, cortesías o pagos parciales.

  • Al marcar una cita como completada, el sistema sugiere abrir el registro de pago con el monto del servicio precargado.
  • Los ingresos aparecen en el dashboard del día en tiempo real.
  • El módulo de abonos (Payment.html) permite confirmar depósitos previos desde un enlace externo.

Gestión de empleados

El administrador gestiona el equipo del salón: roles, servicios que puede realizar cada uno y PINs de acceso para sesiones individuales en el panel.

◉

Perfiles del equipo

Nombre, rol (Estilista, Colorista, Barbero, etc.) y estado activo/inactivo. Solo los activos aparecen en el portal de reservas.

Roles disponibles
✦

Servicios por empleado

Cada empleado tiene asignados los servicios que domina. El portal de reservas solo ofrece estilistas habilitados para el servicio elegido.

Inteligente
⊛

PINs de acceso

Cada empleado tiene un PIN numérico. Con él puede iniciar sesión en el panel y ver solo sus citas del día sin acceso al resto del sistema.

Sesión propia
⊙

Vista del empleado

Al entrar con PIN, el empleado ve su agenda personal: citas asignadas, clientes y puede cambiar estados sin permisos de admin.

⊘

Activar / desactivar

Un toggle desactiva un empleado sin borrarlo. Sus citas históricas se conservan; solo deja de aparecer en nuevas reservas.

Admin · Módulo

Bloqueo de horarios

El administrador puede bloquear franjas horarias específicas para evitar que los clientes reserven en horas no disponibles: vacaciones, formaciones, eventos.

  • Selecciona fecha, hora y opcionalmente el estilista afectado. O bloquea el horario completo para todos.
  • Los slots bloqueados aparecen deshabilitados automáticamente en el portal de agendamiento del cliente.
  • Lista de bloqueos activos con botón para eliminarlos cuando ya no aplican.
  • Compatible con la vista de agenda semanal: los bloqueos aparecen marcados visualmente.
⊛
Admin · Externo

Confirmación de abonos

Módulo independiente para confirmar depósitos o abonos de clientes. Accedido con contraseña de admin, permite verificar y registrar pagos parciales vinculados a una cita.

  • URL independiente accesible por link único con parámetro de ID de pago.
  • Autenticación propia con contraseña de administrador.
  • Muestra los datos del pago pendiente y permite confirmar o rechazar el abono.
  • Útil para pagos anticipados o depósitos de garantía en servicios de larga duración.

Técnico

Arquitectura del sistema

El sistema está construido para funcionar sin frameworks pesados ni build steps. Solo HTML, React via CDN y API routes en Vercel. Fácil de mantener y de desplegar.

◈

Sin build step

React cargado via CDN con Babel standalone. No hay bundler, no hay npm build. Deploy instantáneo.

Simple
≡

Turso como base de datos

SQLite distribuida via Turso. Los datos persisten entre sesiones y se sincronizan entre todas las pantallas abiertas.

Persistencia
→

BroadcastChannel

Sincronización instantánea entre pestañas del mismo navegador sin recargar. Ideal para tener admin + lobby + escáner abiertos simultáneamente.

Tiempo real
⊙

Cache offline

localStorage como caché. Si el servidor no responde, el sistema sigue funcionando con los últimos datos. Sincroniza en cuanto vuelve la conexión.

Resiliente
◉

API Routes en Vercel

Endpoints en /api: store, admin, crm, catalog, auth, client, payment. Cada uno con autenticación Bearer token.

Serverless
✦

QR generado en cliente

Los códigos QR se generan en el navegador con SVG puro, sin librerías externas. Cada ticket tiene su QR único basado en el ID de la cita.

Zero-dep
◎

Seguridad de la API

Rate limiting por IP en el endpoint de reservas, validación estricta de campos, CORS configurado y funciones crypto en la capa de base de datos.

Hardened
⊙

Auth gate del portal

El portal de clientes exige autenticación antes de mostrar cualquier dato. Admins y empleados acceden con contraseña o PIN respectivamente.

Seguro
API endpoints
GET /api/store Citas, cola activa y horarios bloqueados
GET /api/admin Configuración, servicios, empleados, ingresos
GET /api/crm Perfiles y historial de clientes
GET /api/catalog Servicios y empleados públicos (sin auth)
POST /api/auth Autenticación admin y empleados por PIN
POST /api/book Crea una cita con validación de campos, rate limiting y notificación push al admin
POST /api/agenda Login de empleado por PIN y confirmación de cita asignada
GET /api/push Gestión de suscripciones de notificaciones push (Web Push / VAPID)
